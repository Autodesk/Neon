# Carbon test suite

One CTest entry per source file in this directory. The `Scope` column indicates
the hardware the test exercises:

- **CPU only** — host-side logic only; no CUDA devices required.
- **Multi-GPU** — single-process; constructs a `System` over every visible
  device via `carbon::get_all_devices()`. Degrades to one device on a
  single-GPU machine.
- **Multi-GPU (≥2 GPUs)** — single-process but specifically exercises a code
  path that requires at least two CUDA devices. Skipped gracefully otherwise.
- **Distributed multi-GPU** — multi-process; launched under `mpiexec` and
  uses NCCL. Built only when `CARBON_ENABLE_MPI=ON`.

CTest also registers `carbon_format_check` (no source file): a `clang-format --dry-run --Werror`
pass over `include/`, `src/`, `tests/`, and `examples/`. Listed at the bottom of the table for
completeness.

| --- | --- | --- |
| `test_data_view.cpp` | `DataView` enum: count, integer values, `to_string` / `to_int`, stream insertion, exception on out-of-range conversion. | CPU only |
| `test_dynamic_load.cpp` | Smoke-tests dynamic loading of `libcarbon`: `carbon::init()` followed by a version probe through `carbon::info()`. | CPU only |
| `test_logging.cpp` | Logging smoke test: `carbon::init()` plus a single `CARBON_LOG_INFO` call to verify the spdlog wiring. | CPU only |
| `test_memory_side.cpp` | `MemorySide` enum: count, integer values, `to_string` / `to_int`, stream insertion, exception on out-of-range conversion. | CPU only |
| `test_stencil.cpp` | `Stencil` construction from point lists; verifies radius computation, point storage, and the empty-stencil case. | CPU only |
| `test_transfer.cpp` | Host-only `BufferGroup<T>` transfer: builds two single-entry host buffer groups and exercises `Transfer` on the CPU side without touching CUDA. | CPU only |
| `test_gpu.cpp` | `device_count()`, `GpuGroup` default construction, multi-allocation buffer groups, `StreamGroup` / `EventGroup` sizing across all visible devices. | Multi-GPU |
| `test_gpu_group_all_devices.cpp` | Builds a `GpuGroup` from `get_all_devices()` and verifies device-id ordering matches the CUDA device enumeration. | Multi-GPU |
| `test_dense.cpp` | `Dense` API: empty-`GpuGroup` edge case plus partition layout consistency over a `System` built from `get_all_devices()`. | Multi-GPU |
| `test_dense_kernel.cu` | Launches a `Kernel` over a multi-GPU `Dense` grid using `Partition` / `Span` and verifies per-cell results on the host after a download. | Multi-GPU |
| `test_partition_read.cu` | `Partition::read` across per-GPU `Span`s on a no-halo `Dense` grid; verifies coordinate-encoded reads from every owned cell. | Multi-GPU |
| `test_partition_halo.cu` | Halo-aware `Partition` + `Span` with `Stencil` radius > 0; kernel reads `(0, 0, ±1)` neighbours through the lower/upper z halos to validate halo arithmetic. | Multi-GPU |
| `test_transfer_cuda.cu` | Host ↔ device `async_copy` round-trip via `Transfer` over multi-GPU `BufferGroup`s, one allocation per visible device. | Multi-GPU |
| `test_integration.cu` | End-to-end `Dense` + `Field` + `Transfer` + `Kernel`: host → device upload, in-place `*= 2` kernel using `Partition`/`Span`, device → host download, full-grid verification. | Multi-GPU |
| `test_transfer_peer.cu` | `cudaMemcpyPeerAsync` path of `System::async_copy`: builds two single-entry device `BufferGroup`s on different GPUs and runs a peer `Transfer`. Skipped when fewer than two CUDA devices are visible. | Multi-GPU (≥2 GPUs) |
| `test_kernel_laplacian_single_gpu.cu` | First numerical-correctness kernel: forces a one-GPU `System`, builds a `Dense` with a radius-1 stencil so storage carries z-halos (filled on host with the same input), and runs a 7-point discrete Laplacian on `f(x, y, z) = a x² + b y² + c z²`. Verifies every owned cell on the strict (x, y) interior equals exactly `2(a + b + c)`. Two passes: `T = int32_t` (tight integer reference) and `T = float` (cross-check the same exact value). Exercises `Partition::read` / `write`, `Span::make_idx`, full host ↔ device round-trip. | Multi-GPU |
| `test_data_view_split.cu` | `DataView` split correctness: forces a one-GPU `System` with a radius-1 stencil so `halo_z = 1`, builds two output fields `u_std` and `u_split` over the same `Dense`, runs the same coordinate-encoding kernel under `DataView::Standard` on `u_std` and under `DataView::Internal` then `DataView::Boundary` on `u_split`, then verifies (a) every owned cell on `u_split` equals the matching cell on `u_std` bit-for-bit, (b) every halo cell on `u_split` is still the sentinel (Internal / Boundary must not write outside the owned region), (c) the iteration extents reported by `Span::iter_extent` for the three views match the expected `(Lz, Lz - 2*halo_z, 2*halo_z)`. Locks the contract that `Standard == Internal + Boundary` cell-by-cell. | Multi-GPU |
| `test_data_view_split_jacobi.cu` | Multi-stream Jacobi using the data-view split with overlapped halo exchange. Runs a 7-point Jacobi smoothing kernel on a multi-GPU `Dense` (radius-1 stencil, Open BC) for 20 ping-pong iterations along two paths: (a) a reference path that issues `halo(u_in)` then a `Standard` kernel launch on a single stream per iteration, and (b) a test path that runs Internal on a compute stream concurrently with `halo(u_in)` on a halo stream, gates Boundary behind a `cudaEventRecord` on the halo stream + `cudaStreamWaitEvent` on the compute stream, and gates the next iteration's halo behind a `cudaEventRecord` on the compute stream + `cudaStreamWaitEvent` on the halo stream. After the 20 iterations completes, downloads both final fields and compares every owned cell bit-for-bit. A missed sync (Boundary running before halo, halo running before the previous iteration's Boundary writes, etc.) drifts the two fields apart and the per-cell check fires. Single-GPU runs work too — `Halo` is a no-op when there are no neighbour slabs, but the orchestration mechanics (events, stream waits, swap) are still exercised. | Multi-GPU |
| `test_halo_single_node.cu` | Single-node intra-process `Halo<T, Components>` exchange on an `Open` boundary `Dense` with `halo_z = 1`: fills owned cells with `encode(x, y, global_z)`, sentinel-fills halo cells, runs `Halo` on a stream, and verifies (a) interior halo regions on every slab now hold the encoded value of the global cell they represent (proves up/down pairings, source/destination offsets, and per-pair counts are correct), (b) owned cells are unchanged, (c) exterior halos (slab 0 lower, slab N-1 upper) remain at the sentinel. Skipped gracefully when fewer than two CUDA devices are visible. | Multi-GPU (≥2 GPUs) |
| `test_halo_periodic_z.cu` | Single-process `Halo<T, Components>` exchange on a `PeriodicZ` `Dense` with `halo_z = 1`: same encoder shape as `test_halo_single_node`, but PeriodicZ adds the wrap pair (slab N-1 ↔ slab 0). Verifies every cell (owned + halos, including the wrap halos on slab 0's lower and slab N-1's upper) matches `encode(x, y, wrapped_global_z)` and asserts `pair_count() == 2 * n_gpus` (regular pairs + wrap pair). Also exercises the single-slab self-wrap branch when run on a single visible CUDA device. | Multi-GPU |
| `test_field_fill_host.cu` | `Field::fill_owned_host` smoke test: pre-fills the host mirror with a sentinel, calls `fill_owned_host` with an encoder of `(global_x, global_y, global_z)`, then verifies (a) owned cells now hold `encode(x, y, global_z)`, (b) halo cells are still the sentinel (the API must not write into the halo region), (c) the result survives a host → device → host round-trip unchanged. Also exercises the throw path: a `MemorySide::Device`-only field rejects `fill_owned_host` with `std::invalid_argument` because there is no host mirror. | Multi-GPU |
| `test_native_io.cu` | `carbon::io::write_native` / `read_native` round-trip: writes a scalar `float` field and a 3-component `int32_t` vector field to the same shard, reads them back into fresh fields, and verifies (a) owned cells match the original encoders bit-for-bit, (b) halo cells are not touched by I/O, (c) dtype and component-count mismatches at read time throw `std::invalid_argument`. | Multi-GPU |
| `test_reduce_sum.cu` | Single-GPU `ReduceKernel` + `ReductionResult<T>` correctness against `reduce::Sum<T>`. Forces a one-GPU `System`, builds a `Dense` (24×32×16, no halo), and runs four cases: (1) `int64_t` sum of a deterministic per-cell encoding, compared bit-for-bit against a host reference; (2) `double` sum over the same encoding, compared with a `1e-9` relative tolerance; (3) empty-domain reduce (`z = 0`), which must return the operator's identity (0) without launching a stage-1 block; (4) re-launch into the same `ReductionResult` (overwrite, not accumulate). Asserts `block_count() == ceil(total_cells / 256)` so the launch shape stays consistent with the fused `cub::BlockReduce` kernel. | Multi-GPU |
| `test_hdf5_io.cu` | `carbon::io::write_hdf5` / `read_hdf5` round-trip: same shape as `test_native_io` but writes to an HDF5 file (one dataset per field with rank-4 shape `(Components, global.z, global.y, global.x)`). Compiles to a no-op smoke test when `CARBON_HAVE_HDF5` is not defined. Single-process today; the parallel HDF5 path runs under MPI when carbon is built with `CARBON_ENABLE_HDF5=ON` against a parallel HDF5 install. | Multi-GPU |
| `test_vtk_io.cu` | `carbon::io::write_vtk` / `read_vtk` round-trip: writes the same scalar `float` + 3-component `int32_t` fields used by `test_native_io` to a legacy VTK STRUCTURED_POINTS BINARY file (one SCALARS block per field under POINT_DATA, big-endian payload, component-fastest interleaving), reads them back, and verifies bit-for-bit equality on owned cells, halos untouched, dtype mismatches throw, and DIMENSIONS-mismatch reads are rejected. Pure stdlib, no external dependency, always built. The on-disk format is the non-XML legacy `*.vtk` ParaView ingests directly. | Multi-GPU |
| `test_nanovdb_io.cu` | `carbon::io::write_nanovdb` / `read_nanovdb` round-trip: same shape as `test_hdf5_io` but writes to a multi-grid `.nvdb` file (one `nanovdb::build::Grid<T>` per `(field, component)`, packed via `nanovdb::io::writeGrids`; the scalar field becomes a single grid named `field_0`, the 3-component vector field fans out to `field_1_c0/_c1/_c2`). Verifies bit-for-bit equality on every owned cell after `readGrids` + per-grid accessor scatter, and asserts halos stay at the sentinel. Compiles to a no-op smoke test when `CARBON_HAVE_NANOVDB` is not defined; otherwise nanoVDB is supplied either by `-DCARBON_NANOVDB_INCLUDE_DIR=...`, an installed `find_package(nanovdb)` config, or the FetchContent of OpenVDB pinned by `CARBON_OPENVDB_GIT_TAG` (default `v11.0.0`). Single-process today; nanoVDB has no parallel writer, so multi-rank writes use one file per rank by design. | Multi-GPU |
| `test_dist_transfer.cu` | NCCL cross-rank `Send` / `Recv` round-trip via `DistTransfer<T>`: launched under `mpiexec -n 2`, each rank tags its buffer and exchanges its lower half with the peer's upper half through one grouped transfer. CTest label `distributed`. | Distributed multi-GPU |
| `test_dense_dist.cu` | Distributed-aware `Dense` partitioning under one-rank-per-GPU: launched under `mpiexec -n 2`, each rank verifies `gpu_count() == 1`, `global_slab_count() == world_size`, `local_slab_offset() == world_rank`, and that its single local `Span` carries the correct global z origin / extent (with and without a radius-1 stencil). Picks `global_z = 3 * world_size + 1` to exercise the uneven-split branch. CTest label `distributed`. | Distributed multi-GPU |
| `test_halo_dist.cu` | Cross-rank `Halo<T, Components>` exchange via NCCL `DistTransfer`: launched under `mpiexec -n 2`, each rank fills its single distributed Dense slab with `encode(x, y, global_z)`, sentinel-fills its halos, runs `Halo` on a stream, and verifies (a) interior halos now hold the encoded value of the global cell they represent (proves Send/Recv pairing, byte counts, and per-rank offsets across the NCCL group), (b) owned cells unchanged, (c) exterior halos (rank 0 lower, rank N-1 upper) remain at the sentinel. Also asserts `pair_count() == 0` and `dist_entry_count() == 2 * peer_count` to lock the carbon-MPI one-rank-per-GPU contract. CTest label `distributed`. | Distributed multi-GPU |
| `test_halo_dist_periodic_z.cu` | Cross-rank `Halo<T, Components>` PeriodicZ wrap exchange: launched under `mpiexec -n 2`, each rank builds its distributed Dense with `BoundaryMode::PeriodicZ` and verifies that every halo cell (including rank 0's lower and rank N-1's upper) matches `encode(x, y, wrapped_global_z)` after a wrap-aware NCCL exchange. `dist_entry_count` is uniform across ranks at `2 * Components * 2` (every rank has both up and down peers under PeriodicZ). CTest label `distributed`. | Distributed multi-GPU |
| `test_native_io_dist.cu` | `carbon::io::write_native` / `read_native` distributed (one-shard-per-rank) round-trip: launched under `mpiexec -n 2`, each rank writes its own slab to `<path>.rank<N>`, reads it back into a fresh field, and verifies owned cells match the encoder while halos stay at the sentinel. No cross-rank coordination is performed (native binary uses one file per rank by design). CTest label `distributed`. | Distributed multi-GPU |
| _(no source)_ `carbon_format_check` | `clang-format --dry-run --Werror` over the formatted source globs. Skipped when `clang-format` is not on `PATH`. | CPU only |
